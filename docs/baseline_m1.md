# M1 原始检测与跟踪基线

2026-09-30，02 在 `data/tabletop_02.mp4` 上实际运行 YOLO11n + ByteTrack。
可交付结果为 `outputs/tabletop_02_baseline_v2/`。984 条记录、984 次跟踪器更新与带框视频重新解码的 984 帧一致，核查通过。
本轮只观察原始基线，没有失效状态机或自定义恢复模块。输入为开发视频，尚无独立测试与身份/遮挡事件标注。

## 固定运行条件

- Python 3.12.3；Ultralytics 8.3.221；torch 2.8.0+cu128；torchvision 0.23.0+cu128。
- OpenCV 4.12.0（opencv-python 4.12.0.88）；NumPy 2.2.6；lap 0.5.12；SciPy 1.18.1；PyYAML 6.0.3。
- GPU：RTX 4070 Laptop；32×32 全一矩阵乘法结果为 32，完整模型 GPU 推理通过。沙箱内 CUDA 不可见，运行在沙箱外完成。
- 权重 `weights/yolo11n.pt` 与从官方发布 URL 重新下载的文件 SHA-256 一致：`0ebbc80d4a7680d14987a577cd21342b65ecfd94632bd9a8da63ae6417644ee1`。
- 类别 `bottle`（COCO ID 39）；imgsz=640、conf=0.1、NMS IoU=0.7。类别过滤不能识别红盖或指定目标身份。
- 默认 ByteTrack 参数：high=0.25、low=0.1、new=0.25、buffer=30、match=0.8、fuse_score=true。构造 frame_rate=30，与固定版本官方集成入口一致；有效保留上限为 30 帧，按本视频名义 FPS 约 1.03 秒。

命令从项目根目录执行；重复实验须换新输出目录：

```bash
.venv/bin/python scripts/run_baseline.py --source data/tabletop_02.mp4 --output outputs/tabletop_02_baseline_v2 --model weights/yolo11n.pt --device 0 --imgsz 640 --conf 0.1 --iou 0.7
.venv/bin/python scripts/review_baseline.py --output outputs/tabletop_02_baseline_v2 --frames 227 693 694 844 845 847 848
```

## 从帧到框，再到 ID

OpenCV 每次解码一帧像素，YOLO 做缩放与预处理、推理和 NMS，输出原图坐标中的检测框、类别、检测分数。
脚本完整保留筛选后的检测；每帧都调用原生 `BYTETracker.update`，空检测帧也推进跟踪器。
ByteTrack 根据 Kalman 运动预测与框重叠进行匹配，高分检测先关联，再用低分检测关联仍在跟踪的轨迹；符合条件的高分框可以新建轨迹。
在本版本中，丢失轨迹也参与高分第一轮关联，允许在缓冲期内以原 ID 重新激活；没有外观 ReID 或相机运动补偿。

上述是原始跟踪器的能力，不是本项目新增恢复贡献。该实现和配置均未修改。
项目新增的是逐帧调用与证据保存、检测/轨迹索引映射、视频绘制及输出核查。
本轮 `custom_recovery_enabled=false`；以后新增模块时，以本结果作为关闭模块的原始对照，当前尚未进行消融实验。

示例：f845 检测到局部瓶身，检测分数约 0.154，`track_id=null`；f847 分数升至约 0.861，建立尚未确认的新轨迹；f848 获得可输出的 ID 5。
因此，“有检测框”和“已有轨迹 ID”是不同步骤。检测分数也不是身份或跟踪可靠性的概率。

## 实际观察与失败案例

以下时间均按帧索引/名义 FPS 估算；检测区间不是人工遮挡事件标注。范围两端的帧索引均包含。

| 观察 | 帧及估算时间 | 证据与边界 |
| --- | --- | --- |
| 初始瓶子 ID 1 | f0—163，约 0—5.65 秒 | 开头检测稳定，已查看带框首帧与每秒预览 |
| 镜头遮挡后 ID 2 | f220—385，约 7.58—13.29 秒 | 中间背景也被遮住且视角变化；不能与后半段局部目标遮挡混作同一事件类型 |
| 误检轨迹 ID 3 | f223—229，约 7.68—7.92 秒 | f227 的框覆盖挂包与衣柜区域，非主要红盖瓶子；已查看 `frame_000227.jpg`，保留为失败证据 |
| 第二次画面中断后 ID 4 | f517—693，约 17.80—23.90 秒 | 查看预览，红盖瓶子出现在较远位置；ID 改变，尚无身份指标 |
| 纸板遮挡区间无瓶子检测 | f694—844，约 23.90—29.10 秒 | 连续 151 帧空检测，预览中纸板遮住目标、背景可见；不绘制隐藏目标的预测位置 |
| 纸板移开后新 ID 5 | f848—983，约 29.20—33.89 秒 | f845—847 已有检测但无输出 ID；查看 f845/f848，瓶子在新位置显露 |

后半段空检测时长约 5.20 秒，超过默认 30 帧缓冲，同时目标位移；本次旧 ID 4 未延续，重现后是新 ID 5。
这证明本次运行的 ID 变化，不能单独证明物理目标身份或任何恢复策略的成功。
同一红盖瓶子的外观与用户描述可作为后续人工核查线索；尚未形成正式身份标注、重现时刻标注或错误恢复指标。
长遮挡与位移、默认缓冲、模型误检是后续应分别处理的因素，当前未通过对照实验分离它们的影响。

单次实测 650 帧有检测、643 帧有输出轨迹；计时循环约 10.30 秒、95.53 帧/秒。
计时包含首次推理初始化、解码、推理、关联、绘制、JSON 与视频写入，排除模型加载、GPU 检查和最终编码器释放。
这是该设备上一次运行的处理速度，不是严格性能基准，也不是准确率、目标可见率或实时系统保证。

## 核查与已知限制

- 已核查连续帧索引、时间依据、检测分数、检测与轨迹关联映射、ID 统计以及视频帧数/尺寸；已查看首帧、每秒预览及 f227、f845、f848。
- 第一轮 `outputs/tabletop_02_baseline/` 在 f227 核查失败：把跟踪器返回的分数子集索引误当作完整检测索引。该目录保留为排错证据，不作基线。v2 只修正输出映射：依原 YAML 高低分掩码还原原始索引，未改关联算法/框/分数/ID；修正后重新跑全视频并核查通过。
- 视频、权重、环境、缓存和全部输出仅在本地。输出视频为 mp4v MP4、名义恒定帧率、无音频；源时间同时保存为 `source_pos_msec_seconds`，本次报告时间单调，末帧约 33.854 秒。解码帧数一致不保证源视频绝对完整。
- 完全不可见时位置未知；空检测也可能由漏检导致，当前无“遮挡/丢失/恢复”状态分类。
- 两段视频均为开发输入。未运行恢复模块、公平对照或独立测试，不给出泛化性能结论。
